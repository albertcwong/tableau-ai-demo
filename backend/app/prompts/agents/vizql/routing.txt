## Classification Task

Classify this user query into ONE of three types:

### 1. schema_query
Questions answerable from enriched schema metadata ONLY (no data querying needed).

**CRITICAL DISTINCTION:**
- "How many [field]?" = Check field cardinality (distinct count) → `schema_query`
- "Count [field]" or "Total count of [field]" = COUNT aggregation → `new_query`
- "How many [field] by [dimension]?" = Grouped count → `new_query`

**Indicators:**
- Asks about field properties: "how many distinct", "what's the min/max", "what's the data type"
- Asks about available fields: "what fields", "what measures", "what dimensions"
- Asks about schema structure: "how many fields", "list all categories"
- References field cardinality, statistics, or metadata
- Does NOT require aggregating data values
- Simple "how many [field]?" without grouping/filtering → `schema_query`

**Keywords:** "how many [field]", "what [fields]", "min/max", "data type", "available", "distinct values", "field list"

**Examples (schema_query):**
- "How many customers do we have?" → Check Customer cardinality (schema_query)
- "How many products?" → Check Product cardinality (schema_query)
- "How many distinct customers?" → Check Customer cardinality (schema_query)
- "What's the min and max sales?" → Check Sales min/max (schema_query)
- "What regions are available?" → Check Region sample_values (schema_query)
- "List all product categories" → Check Category sample_values (schema_query)
- "How many fields are in this dataset?" → Count schema fields (schema_query)

**NOT schema_query (these are new_query):**
- "Count customers by region" → Requires COUNT aggregation with grouping (new_query)
- "How many customers in 2024?" → Requires filtering (new_query)
- "Total number of orders" → Requires COUNT aggregation (new_query)

### 2. reformat_previous
Requests to reformat, reorganize, or filter EXISTING query results (no new query needed).

**Indicators:**
- References previous results: "the results", "that", "those", "them", "it"
- Asks for reformatting: "put in a table", "show as", "format as", "display as"
- Asks to filter/sort existing results: "show only top N", "sort by", "filter"
- Asks to summarize existing results: "summarize", "key insights", "what does this mean"
- REQUIRES previous_results to exist in context

**Keywords:** "the results", "put in a table", "show as", "format", "those", "that", "summarize", "top N from those"

**Examples:**
- "Put the results in a table"
- "Show that as a chart"
- "Format as JSON"
- "Summarize those results"
- "Show only the top 5"
- "What does this data mean?"

**CRITICAL:** Only classify as reformat_previous if previous results exist!

### 3. new_query
Requires constructing and executing a NEW VizQL query to aggregate/filter/compute data.

**Indicators:**
- Asks for data aggregation: "total", "sum", "average", "count of sales"
- Asks for grouping: "by region", "per category", "for each"
- Asks for filtering data: "where", "in 2024", "greater than"
- Asks for calculations: "profit margin", "percentage", "ratio"
- Requires querying actual data values (not just schema metadata)

**Keywords:** "total", "sum", "average", "by", "per", "where", "in", "for", "top N by [measure]", "show me"

**Examples:**
- "Show me total sales by region"
- "Top 10 customers by revenue"
- "Average price per product"
- "Sales in 2024"
- "Products with revenue > 10000"

## Decision Rules

1. **"How many [field]?" WITHOUT grouping/filtering** → `schema_query` (check cardinality)
   - "How many customers?" → schema_query
   - "How many products?" → schema_query
   - "How many distinct customers?" → schema_query

2. **"How many [field]?" WITH grouping/filtering** → `new_query` (requires aggregation)
   - "How many customers by region?" → new_query
   - "How many customers in 2024?" → new_query
   - "Count customers where sales > 1000" → new_query

3. **Asking about field metadata/statistics** (min/max, available values, data types) → `schema_query`
   - "What's the min and max sales?" → schema_query
   - "What regions are available?" → schema_query
   - "What's the data type of Price?" → schema_query

4. **If referencing previous results AND asking to reformat** → `reformat_previous`

5. **If requires data aggregation/filtering/computation** → `new_query`
   - "Total sales", "Average price", "Sum of revenue" → new_query
   - "Top N by measure" → new_query
   - "Sales where condition" → new_query

6. **When in doubt about "how many [field]?"** → `schema_query` (check cardinality first, faster)
